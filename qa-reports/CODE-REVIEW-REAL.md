### Findings

**1. med — The last `degrade()` stage recompiles every shader on the main thread.** `scene.js:369` sets `renderer.shadowMap.enabled = false` and `needsUpdate = true` on every material. Shadow state is part of each program's key, so the next frame recompiles and links all programs synchronously (several hundred ms to seconds), exactly on the slow machines that triggered the step-down (BRIEF-3D-REAL: no main-thread block over ~250 ms). The lights and casters are static, so the shadow can simply be frozen. Fix: replace the branch with `if (renderer.shadowMap.autoUpdate) { renderer.shadowMap.autoUpdate = false; renderer.shadowMap.needsUpdate = true; return; }` (keeps the last shadow map, no recompile). After a context restore, set `renderer.shadowMap.needsUpdate = true` in `onRestored`.

**2. med — The full-screen mobile menu cannot scroll on short screens (320x256).** `style.css:104-107`: `.nav__menu` is `position: fixed; inset: 0; display: flex; align-items: center` with four 56 px links + 12 px gaps ≈ 260 px. At 256 px tall the column overflows both ends: the first link ("The cut") sits under the 66 px header (`.nav__inner` is `z-index: 2` over the menu's `z-index: 1`) and "Reserve" is cut off at the bottom; there is no `overflow`, the page is locked, and a stopped Lenis `preventDefault`s wheel/touch. Fix: `.nav__menu { overflow-y: auto; overscroll-behavior: contain; align-items: safe center; padding-block: var(--nav-h) var(--s-5); }` plus `data-lenis-prevent` on `#navMenu` (`index.html:28`); optionally `@media (max-height: 420px) { .nav__links a { font-size: 1.25rem; min-height: 44px; } }`.

**3. low (verify at 320x568) — The reserve panel may be taller than its sticky frame on small phones.** `style.css:160` pins `.station__stick` at `height: 100svh`; the unstick query is `max-height: 560px` (`:237`), so a 320x568 phone keeps the pin with about 474 px for the panel (568 − 78 − 16). By my estimate the reserve panel at 280 px content width (3-line `h2`, 5-line paragraph, wrapped CTA row, three wrapped `dd`s, testimonial note) is ~630 px, so its bottom overflows the pinned frame (the round-2 forno-rosso pattern). Measure it; if it overflows, widen the unstick query to `@media (max-height: 560px), (max-width: 400px) and (max-height: 700px)`.

**4. low — A context loss during stage A is not caught.** The `webglcontextlost`/`restored` listeners are attached at `scene.js:394-395`, after stage A has loaded. A loss before that is not `preventDefault`ed (so it never restores), `lost` stays `false`, `ready = true` and `onReady` adds `is-3d` (`:403-406`): posters hide over a dead canvas. Fix: attach both listeners right after the renderer is created (`:65`), and change `:403` to `if (lost || renderer.getContext().isContextLost()) return null;`.

**5. low — Post programs still compile on the first composed frame.** `compilePost()` (`:115-129`) compiles every pass material against `composer.readBuffer`, but (a) `OutputPass` gets its `SRGB_TRANSFER`/`ACES_FILMIC_TONE_MAPPING` defines only inside `render()`, so the compiled variant is never used, and (b) the last pass (`grade`) renders to the screen, a different program key (tone mapping and output colour space are in the key). Fix as in himal-chulo (`scene.js:1168-1176` there): set `output.material.defines = { SRGB_TRANSFER: '', ACES_FILMIC_TONE_MAPPING: '' }` (and `_outputColorSpace`/`_toneMapping`) before compiling, and compile `grade.material` with `setRenderTarget(null)`. Also, after a restore `makeComposer()` brings back the heat pass that `degrade()` had removed; keep a `heatOff` flag.

**6. low — The GSAP ticker runs a 60 Hz rAF for ever under reduced motion.** `main.js:8` enables GSAP regardless of `reduce`, and the ScrollTrigger at `:124` keeps the ticker awake, while the pause button is hidden under reduced motion, so there is no way to stop it. Fix (as himal-chulo `main.js:9-13`): `const hasGsap = !reduce && ...;` and under `reduce` call `ScrollTrigger.disable(false); gsap.ticker.sleep();`.

**7. low — The 1-px ARM stand-in turns the lamp shade non-metallic.** `scene.js:84`, `:88`: `hanging_industrial_lamp_arm` is swapped for `rgb(255,205,0)` (metalness 0), so the iron shade renders as matte plastic. Fix: after loading the lamp, for its non-glass materials set `m.metalnessMap = null; m.metalness = 1; m.roughnessMap = null; m.roughness = 0.45;`.

**8. low — HDR texture kept on the GPU; desktop slightly over budget.** `scene.js:146` never releases the 1k equirect upload after PMREM (~4 MB VRAM): add `hdr.dispose()` after `fromEquirectangular` (the CPU data stays for a restore). Desktop total 12.8 MB vs ~12 MB: skipping the onion's 0.6 MB or the board's normal map brings it under.

**Verdict: CHANGES NEEDED** (findings 1 and 2, med).

### Findings

**1. med — Late props are attached to the live scene before their textures are uploaded and their programs compiled.** `scene.js:375-381`: `add(g)` (the `world.addX` functions put visible clones straight into the scene) runs before `await upload(g)` and `compileAsync`. Fix: prepare first, attach after: `await upload(g); if (composer) renderer.setRenderTarget(composer.readBuffer); await withTimeout(renderer.compileAsync(g, camera, scene), 4000); renderer.setRenderTarget(null); add(g);` (the clones made inside `add` share `g`'s materials and textures, and `addPlant`'s `alphaTest` change keeps the same define).

**2. med — Bloom's programs compile synchronously when it is switched on.** Bloom starts disabled and is enabled in idle time (`scene.js:386-389`), but its eight `ShaderMaterial`s are never precompiled, so `bloom.enabled = true; draw()` compiles and links them in one task: the round-2 forno-rosso stall, moved to the middle of the visit (`requestIdleCallback` with a 400 ms timeout fires during scrolling too). `OutputPass`, FXAA and grain are not precompiled before the first frame either (`:306-308` compiles only the scene).
